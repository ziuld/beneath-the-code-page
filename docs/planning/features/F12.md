## F12-UH01 — Discover the published MVP JSON tools

As a visitor, I want to find and open each available developer tool, so that I can choose the right operation.

Parent: F12. Priority: Must. Status: planned. Owner: Ziuld with AI assistance.
Estimate: 6h baseline / 2h forecast. Dependencies: F07.

V1 catalogue integration only: Formatter, Validator and Minifier; F08–F11 remain frozen for V2.

### EARS requirements

| ID | Pattern | Required behaviour |
|---|---|---|
| F12-UH01-R01 | event | When the Tools catalogue is opened, Beneath the Code shall list only the published F06 and F07 JSON tools with working destinations. |
| F12-UH01-R02 | unwanted | If an unknown tool identifier is requested, then Beneath the Code shall return a localised 404. |

## F12-UH02 — Verify the existing packaged application locally

As a maintainer, I want to use the existing packaged-JAR workflow, so that I can verify the MVP without adding container infrastructure.

Parent: F12. Priority: Must. Status: planned. Owner: Ziuld with AI assistance.
Estimate: 8h baseline / 2h forecast. Dependencies: F12-UH01.

Reuse the existing packaged-JAR workflow and applicable security evidence. Docker/Compose and container-specific hardening/scans are V2, not an MVP prerequisite.

### EARS requirements

| ID | Pattern | Required behaviour |
|---|---|---|
| F12-UH02-R01 | event | When the documented local packaged-JAR workflow starts, the application shall become healthy using loopback application access without a publicly exposed management endpoint. |
| F12-UH02-R02 | unwanted | If an integrated security scan reports an unresolved blocking finding, then release verification shall fail. |

  As a maintainer, I want to use the existing packaged-JAR workflow, so that I can verify the MVP without adding container infrastructure.

  @F12-UH02-AC01 @F12-UH02-R01
  Scenario: Start the local runtime
    Given the executable JAR is built and documented prerequisites are available
    When the maintainer follows the existing local JAR workflow
