## F11-UH01 — Convert supported JSON to YAML faithfully

As a developer, I want to convert JSON to YAML without silent data loss, so that I can change notation while retaining meaning.

Parent: F11. Priority: Must. Status: planned. Owner: Ziuld with AI assistance.
Estimate: 12h baseline / 12h forecast. Dependencies: F07.

Implements the accepted feature scope; no additional product capabilities implied.

### EARS requirements

| ID | Pattern | Required behaviour |
|---|---|---|
| F11-UH01-R01 | event | When supported JSON is converted to YAML, the converter shall preserve its JSON values and structure. |
| F11-UH01-R02 | unwanted | If JSON contains duplicate object keys, then the converter shall reject the conversion as ambiguous. |

### Gherkin acceptance scenarios

[Standalone Gherkin file](../gherkin/F11-UH01.feature). Specifications only: no step definitions or Cucumber runtime have been installed.

```gherkin
@EPIC-MVP @F11 @F11-UH01
Feature: F11-UH01 — Convert supported JSON to YAML faithfully
  As a developer, I want to convert JSON to YAML without silent data loss, so that I can change notation while retaining meaning.

  @F11-UH01-AC01 @F11-UH01-R01
  Scenario: Convert an ordinary JSON document
    Given the JSON contains strings, finite supported numbers, booleans, null and arrays
    When the developer converts it to YAML
    Then parsing the result under the documented schema yields equivalent values and structure

  @F11-UH01-AC02 @F11-UH01-R02
  Scenario: Reject duplicate-key conversion
    Given the JSON is {"a":1,"a":2}
    When the developer requests YAML conversion
    Then an ambiguity diagnostic appears without a lossy output
```

## F11-UH02 — Convert supported YAML to strict JSON

As a developer, I want to convert a safe YAML subset to JSON, so that I can use configuration values in JSON tools.

Parent: F11. Priority: Must. Status: planned. Owner: Ziuld with AI assistance.
Estimate: 12h baseline / 12h forecast. Dependencies: F11-UH01.

Implements the accepted feature scope; no additional product capabilities implied.

### EARS requirements

| ID | Pattern | Required behaviour |
|---|---|---|
| F11-UH02-R01 | event | When a supported single YAML document is converted, the converter shall produce strict JSON with equivalent supported values. |
| F11-UH02-R02 | unwanted | If YAML requests custom tags or exceeds the alias-expansion budget, then the converter shall reject it. |

### Gherkin acceptance scenarios

[Standalone Gherkin file](../gherkin/F11-UH02.feature). Specifications only: no step definitions or Cucumber runtime have been installed.

```gherkin
@EPIC-MVP @F11 @F11-UH02
Feature: F11-UH02 — Convert supported YAML to strict JSON
  As a developer, I want to convert a safe YAML subset to JSON, so that I can use configuration values in JSON tools.

  @F11-UH02-AC01 @F11-UH02-R01
  Scenario: Convert a safe mapping
    Given the YAML is a single document with unique string keys and supported scalar values
    When the developer converts it to JSON
    Then the output is strict JSON representing those values

  @F11-UH02-AC02 @F11-UH02-R02
  Scenario: Reject resource-expanding YAML
    Given the input contains aliases exceeding the configured expansion budget
    When the developer requests conversion
    Then the worker rejects the input without freezing the workspace
```
