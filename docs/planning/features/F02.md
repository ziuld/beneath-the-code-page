## F02-UH01 — Package browser assets with server views

As a maintainer, I want to build versioned browser assets into the application, so that SSR pages use the same tested assets in every environment.

Parent: F02. Priority: Must. Status: planned. Owner: Ziuld with AI assistance.
Estimate: 8h baseline / 8h forecast. Dependencies: F01.

Implements the accepted feature scope; no additional product capabilities implied.

### EARS requirements

| ID | Pattern | Required behaviour |
|---|---|---|
| F02-UH01-R01 | event | When the clean application build succeeds, the packaged application shall serve the hashed browser assets referenced by its rendered pages. |
| F02-UH01-R02 | unwanted | If a required manifest entry is absent, then application startup shall fail with a safe diagnostic. |

## F02-UH02 — See current assets during local development

As a maintainer, I want to serve each rebuilt asset during local development, so that I do not test a stale copy.

Parent: F02. Priority: Must. Status: planned. Owner: Ziuld with AI assistance.
Estimate: 4h baseline / 4h forecast. Dependencies: F02-UH01.

Implements the accepted feature scope; no additional product capabilities implied.

### EARS requirements

| ID | Pattern | Required behaviour |
|---|---|---|
| F02-UH02-R01 | event | When a local asset rebuild completes, the local application shall serve the rebuilt asset on the next page load. |
| F02-UH02-R02 | unwanted | If a production configuration references a local filesystem asset directory, then configuration verification shall fail. |

### Gherkin acceptance scenarios

[Standalone Gherkin file](../gherkin/F02-UH02.feature). Specifications only: no step definitions or Cucumber runtime have been installed.

```gherkin
@EPIC-MVP @F02 @F02-UH02
Feature: F02-UH02 — See current assets during local development
  As a maintainer, I want to serve each rebuilt asset during local development, so that I do not test a stale copy.

  @F02-UH02-AC01 @F02-UH02-R01
  Scenario: Observe a second rebuild
    Given the local server has served the first version of an asset
    When the asset changes and the watcher completes another build
    Then the next page load receives the second version

  @F02-UH02-AC02 @F02-UH02-R02
  Scenario: Reject development paths in production
    Given a production configuration points to a developer filesystem directory
    When configuration verification runs
    Then the production configuration is rejected
```
