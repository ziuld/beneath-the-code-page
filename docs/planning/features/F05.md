## F05-UH01 — Edit content with an accessible shared editor

As a keyboard user, I want to edit and leave the code workspace without a trap, so that I can use the tool with my preferred input method.

Parent: F05. Priority: Must. Status: planned. Owner: Ziuld with AI assistance.
Estimate: 8h baseline / 8h forecast. Dependencies: F04.

Implements the accepted feature scope; no additional product capabilities implied.

### EARS requirements

| ID | Pattern | Required behaviour |
|---|---|---|
| F05-UH01-R01 | event | When a keyboard user invokes the documented editor escape action, the editor shall allow focus to move to the next workspace control. |
| F05-UH01-R02 | state | While the restrictive page CSP is enforced, the editor shall support selection, scrolling and search without prohibited resource loads. |

## F05-UH02 — Run bounded processing without blocking the workspace

As a tool user, I want to cancel or recover from expensive processing, so that a difficult input does not make the tool unusable.

Parent: F05. Priority: Must. Status: planned. Owner: Ziuld with AI assistance.
Estimate: 6h baseline / 6h forecast. Dependencies: F05-UH01.

Implements the accepted feature scope; no additional product capabilities implied.

### EARS requirements

| ID | Pattern | Required behaviour |
|---|---|---|
| F05-UH02-R01 | unwanted | If a worker exceeds the configured execution deadline, then the workspace shall terminate that job and present a localised timeout status. |
| F05-UH02-R02 | unwanted | If a cancelled job produces a late result, then the workspace shall ignore that result. |

### Gherkin acceptance scenarios

[Standalone Gherkin file](../gherkin/F05-UH02.feature). Specifications only: no step definitions or Cucumber runtime have been installed.

```gherkin
@EPIC-MVP @F05 @F05-UH02
Feature: F05-UH02 — Run bounded processing without blocking the workspace
  As a tool user, I want to cancel or recover from expensive processing, so that a difficult input does not make the tool unusable.

  @F05-UH02-AC01 @F05-UH02-R01
  Scenario: Recover from an overlong job
    Given a synthetic worker job runs longer than the initial two-second deadline
    When the deadline expires
    Then the job is terminated and another job can be started

  @F05-UH02-AC02 @F05-UH02-R02
  Scenario: Ignore stale output
    Given job A is cancelled and job B has become current
    When a late response for job A arrives
    Then job B's state and output remain unchanged
```
